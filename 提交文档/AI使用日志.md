原题同时要求登录、匿名和允许时重复填写，也要求单选按人数统计。若简单删除服务端身份，会失去每账号防重和去重人数依据；若把人数直接写成答卷次数，又会偏离原文。AI 先列出空缺并提出解释，本人确认对创建者匿名、服务端保留身份关联和单选双口径。

据此，答卷引用填写者，匿名输出采用白名单；每次提交单独保存，统计既算次数也按账号去重。F01 用 U1 两次填写、U2 一次、U3 全空答验证：4 份/3 人，单选 3 次/2 人，选项人数合计可大于回答人数。这一确认决定了身份引用和统计口径；索引与聚合的具体实现由 AI 完成。

### 案例二：从实际失败修正 Decimal128 均值

W008 发现极值均值聚合中间溢出，AI 增加非有限结果回退；W009 的有限消去反例表明该修复不足。`1E34、1、-1E34` 的精确均值为 1/3，六种排列中的四种曾显示 0.00。AI 将数值来源保持为真实 Mongo BSON，改精确累加，全部排列显示 0.33。

随后正负半分附近四例真实失败，暴露“近似均值再显示”造成的二次舍入。AI 改为从精确总和/计数直接取两位，保留 API Decimal128 输出。原失败记录和新增断言保留，没有调整输入范围或把错误值改成预期。此案例中的反例设计、代码修复、执行和证据整理均由 AI 完成。

### 案例三：从浏览器行为发现接口测试看不到的错误

后端允许 8—128 Unicode 码点密码，但网页曾将 70 个表情截成 64 个，原因是 HTML maxlength 与 Python 码点计数不同。另一条网页流程中，匿名填写回退修改后丢失勾选，虽然接口本身能处理匿名。AI 根据真实网页结果修复前端，重新注册登录，并在回退提交后检查数据库匿名值和内容 API 白名单。

这些例子说明 API 通过不能代替真实交互。回归保留初始失败输入，不只检查页面无报错，也检查最终持久化内容。

### 案例四：检查验收器是否可能遗漏测试

原入口曾允许外部映射缩减测试，且只比较裸函数名，存在参数案例没全部运行却仍能对应函数名的风险。AI 在 P3 清理继承的 pytest 筛选参数并比较实际参数案例，在 P4 固定完整 canonical 集合及 nodeid，额外测试只能追加。

缺映射、失败测试、错误测试库、缩减映射及缺独立记录均被真实执行为失败反例，入口返回非零；这些是专门检查验收器的反例，与开发中实际出现的业务故障分开记录。P4 独立 BSON 核算不导入应用统计函数，降低实现与测试共同犯同类错误的风险，但并不构成“完全正确”的形式化证明。
