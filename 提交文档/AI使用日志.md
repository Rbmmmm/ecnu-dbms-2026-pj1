# AI 使用日志

项目：基于 MongoDB 的问卷系统，第一阶段个人作业。作者：任北鸣。开发时间：2026 年 10 月 15—22 日。

本项目使用 Codex 辅助需求分析、数据库与接口设计、前后端实现及测试修复。部分需求、代码和测试由同模型协作者只读复查。以下按技术任务记录真实提示词摘录、生成内容、采用后的修改及验证结果；提示词保留原文，不把事后总结写成原始指令。代码路径相对仓库根目录。

## 1. 需求澄清与技术选择（10 月 15 日）

**工具与输入**：Codex、助教需求、教材第 3.1/3.2 节及 FastAPI、Flask、MongoDB 官方资料。

**提示词原文摘录**：

> 后端用 Python，框架和前端方案你先比较后推荐，重点考虑作业要求和第二阶段的扩展。

> 先按你推荐的 1A、2A、3A，记录下来，再继续确认跳转、回退修改答案和统计口径。

**AI 产出**：比较后端框架和前端组织方式，推荐 FastAPI + PyMongo + Jinja2 + 原生 JavaScript。对原题未明确的匿名范围、重复填写、发布后编辑、跳转优先级、回退清理及统计单位提出候选解释；本项没有生成业务代码。

**采用与调整**：我指定 Python 和本机运行，接受技术推荐，并确认 16 项业务约定。例如，匿名是对问卷创建者隐藏身份，服务端仍保留账号关联；单选统计同时提供按账号去重的人数和答卷次数。AI 根据这些确认细化行为，没有把补充约定写成原题规定。

这些选择直接影响数据设计。每份答卷单独保存并引用填写者，才能同时支持重复填写、每账号防重和人数统计；匿名输出通过字段白名单控制。方案比较与规则整理由 AI 完成，我参与约束选择和业务取舍。

## 2. MongoDB 结构、接口与路径设计（10 月 15 日）

**工具与输入**：Codex、已确认的业务约定、课程教材及 MongoDB 官方文档。

**提示词原文摘录**：

> 同意，接下来的设计由你直接进行，不需要逐个批准，只需要对照前面所确定的设计原则即可。

**AI 产出**：设计用户、会话、问卷、答卷四个集合及 validator、索引；确定 API、题目和选项稳定 ID、发布版本、答案校验及路径重放规则。相应实现见 `app/db.py`、`app/schemas.py`、`app/domain.py` 和 `app/main.py`。

**采用与修改**：题目和选项嵌入问卷，答卷独立保存；发布后冻结题意，通过内容版本关联答案。提交键与部分唯一索引分别处理重试和每账号防重。AI 在设计检查中补充了回退时的 `pending` 候选、数字内容分页查询，以及截止或关闭竞争中的受理边界。

`pending` 用于处理回退后尚未确定可达的旧答案：确定跳过的答案删除，仍可能重新到达的答案暂存，最终只保存重放确认的路径。上述补充属于设计细化，当时尚未执行业务测试。集合、字段、索引和算法的详细设计由 AI 完成。

## 3. 工程底座与单选完整流程（10 月 15 日）

**工具与输入**：Codex、Python、PyMongo、pytest、真实 MongoDB、Playwright/Chromium；已确认的数据与接口设计。

**提示词原文摘录**：

> 若仍无代码，完成W-005和W-006，目标是P2两账号可运行的单选完整流程

**生成代码**：

- `app/config.py`、`app/db.py`：配置、集合与索引初始化、启动契约和就绪检查。
- `app/schemas.py`、`app/domain.py`、`app/main.py`、`app/statistics.py`：注册登录、创建草稿、发布、链接填写、确认提交、匿名、防重与单选统计。
- `app/templates/page.html`、`app/static/`：管理、编辑、填写和统计页面。

**发现的问题与修改**：删除索引的反例使就绪接口直接抛异常，AI 改为返回 503，并检查真实 validator 与索引。首轮流程测试中，测试客户端重复进入生命周期导致连接池关闭，AI 修正客户端使用方式；另修复短错密码的错误状态、非法 JSON 错误格式，以及响应截断后未冻结原提交的问题。实测发现 `Literal[1]` 接受 `True` 和 `1.0`，又增加了精确整数检查。

**验证**：该阶段 12 项 API/真实数据库案例通过；网页验证确认前不写答卷、原提交键可恢复同一收据，以及应用重启后数据可读。两账号流程和桌面、手机页面均检查。实现、修复和自动执行由 AI 完成。

## 4. 全部题型、校验、跳转与回退（10 月 15 日）

**工具与输入**：Codex、pytest、真实 MongoDB、Playwright/Chromium，以及 Decimal128 和 Python decimal 官方资料。

**提示词原文摘录**：

> 按 11—13 契约完成全部题型、约束、三类跳转和回退答案清理，实际验证 T-03/T-04、F-02 及网页回退流程。

**生成代码**：`app/decimal_values.py`、四题型请求模型、`normalize_answer`、`validate_answer`、`next_target`、`replay`，以及网页题目编辑和回退处理；新增 `tests/fixtures_f02.py`、`tests/test_w007.py`、`tests/browser_w007.cjs`。

**发现的问题与修改**：AI 避免使用默认 decimal 精度规范化输入，以免输入值先被舍入；发现 HTML `maxlength` 按 UTF-16 单元计数，与后端按 Unicode 码点计数不一致后，改为页面显式校验，并实际输入 6000 个表情检查。单选空白统一为 `null`；异步评估增加编号，丢弃过期的成功和错误响应。

原有“多选未实现”测试随本项功能实现改为实际功能断言，仍保留非法类型拒绝和可操作性检查。没有通过降低校验要求消除失败。

**验证**：该阶段累计 55 个参数案例、两套网页流程通过，覆盖 F02 三类路径、回退候选、结束确认及被跳过答案不恢复，并核对真实 BSON 和应用重启后的数据。此时完整统计仍未完成，随后在下一项实现。

## 6. 数值边界与真实网页错误修复（10 月 16 日）

**工具与输入**：Codex、同模型只读复查、pytest、真实 MongoDB、Playwright/Chromium；原始需求和固定样本的独立预期。

**提示词原文摘录**：

> 从助教原始Word及需求Markdown重新审查第一阶段全部业务、测试预期和实际数据

> 不能把P3报告改名当作P4验收

**AI 产出**：新增 `tests/test_p4.py` 和 `tests/browser_p4.cjs`，检查并发 revision、列表与内容分页、题目/选项稳定 ID、数值消去与舍入、revision/offset 上界，以及前端密码和匿名回退行为。

**实际失败与修复**：

- **有限消去**：`1E34、1、-1E34` 的精确均值是 1/3，六种排列中四种曾显示 0.00。AI 改为读取真实 BSON 数值并精确累加，全部排列显示 0.33。
- **双重舍入**：初次修复后，正负半分附近四例仍失败。AI 改为从精确总和与计数直接计算两位显示值，同时保留 API 均值的 Decimal128 精度。
- **整数边界**：按既有契约分别检查 revision 的上界 `2**31-1` 和 offset 的上界 `2**63-1`，避免超界输入进入数据库操作。
- **Unicode 密码**：后端允许 8—128 个码点，网页却曾把 70 个表情截成 64 个。AI 修正页面计数和输入限制，重新验证注册与登录。
- **匿名回退**：填写者回退修改后匿名勾选丢失，AI 修复前端状态，并检查最终数据库值及内容 API 的匿名字段白名单。

首轮新增 API 测试为 5 通过、11 失败，另四个双重舍入案例全部失败；修复后累计 101 个案例及四套网页流程通过。原有单选、全题型和统计测试断言保留。修复记录见[原始故障记录](附件/P4-真实修复记录.json)，具体输入输出见[测试用例与结果](测试用例与结果.md)。

这些错误由 AI 设计的检查和实际运行发现，修复代码也由 AI 完成。我提出重新对照原题和实际数据的检查要求，没有将自动检查写作本人手工验证。

## 7. 测试脚本与数据恢复检查（10 月 16—22 日）

**工具与输入**：Codex、Python/pytest、真实 MongoDB、Playwright/Chromium；六类必测要求、F01/F02 样本及既有测试。

**提示词原文摘录**：

> 从干净配置复现安装启动，在隔离库封存v1四题型、空答、匿名、重复与分支样本并验证重启读取/统计

**生成代码**：`scripts/v1_baseline.py` 保存和恢复第一阶段合成样本，核对 schema、API、字段、题意、路径、统计及应用重启读取；`scripts/test_browser.py` 在独立数据库中启动服务，执行四套原网页脚本，比较重启前后四集合 BSON 数量与摘要，最后清理测试库。

**实际修改**：基线脚本首轮误将统计摘要的 `id` 写为 `question_id`，产生 `KeyError`；第二轮误以为未知存量 schema 会使 health 返回 503。AI 核对实际接口后修正字段，并改为重启应用检查未知版本在启动时被拒绝，保留 health 检查 validator 和索引的原职责。复查还发现 F02 缺少题意与答案的独立逐字段预期，随后补全。以上是测试脚本错误，没有据此修改业务预期。

**验证**：样本包含 4 个合成用户、3 份问卷和 8 份答卷，覆盖四题型、空答、匿名、重复填写及分支；新建和恢复后，字段、路径与统计一致，未知 schema 实际启动拒绝。10 月 22 日在独立 Python 3.11 环境中安装锁定依赖，101 项 API/数据库案例和四套网页流程均通过，应用重启及 v1 新建、恢复检查通过。详细结果见[测试用例与结果](测试用例与结果.md)；本日志的各阶段数量表示当时累计覆盖，不能相加作为不同用例总数。
