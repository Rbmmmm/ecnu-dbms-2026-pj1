# 系统与数据库设计

本系统面向已注册用户，提供问卷创建、四种题型配置、条件跳转、填写提交和统计查询。后端为 FastAPI、PyMongo，页面由 Jinja2 与原生 JavaScript 实现，所有持久业务数据保存在 MongoDB。没有使用关系数据库、现成问卷系统或独立前端框架。

本文描述第一阶段的实际实现；最终验收结果以本次运行证据为准，文字与贡献归属仍需用户审核。

## 1. 系统组成与使用边界

浏览器负责显示题目、收集输入、展示错误和确认结果；后端负责账号身份、问卷归属、配置检查、路径计算、提交资格和统计口径；MongoDB 保存用户、会话、问卷和答卷，并提供唯一约束及聚合查询。

| 模块 | 实际文件 | 职责 |
|---|---|---|
| 页面与交互 | `app/templates/page.html`、`app/static/app.js`、`app/static/style.css` | 编辑、按题填写、回退、提交确认、管理及统计 |
| API 与应用生命周期 | `app/main.py` | 路由、认证、归属检查、状态更新、提交和错误响应 |
| 请求及业务约束 | `app/schemas.py`、`app/domain.py` | 严格字段类型、发布检查、答案规范化和路径重放 |
| 数字、时间及统计 | `app/decimal_values.py`、`app/time_values.py`、`app/statistics.py` | Decimal128 边界、UTC 毫秒时间、聚合及内容分页 |
| 数据库与配置 | `app/db.py`、`app/config.py` | 集合 validator、索引、启动核对及工程上限 |

创建者只能管理自己的问卷及查看对应统计。填写者必须先登录；“匿名”表示创建者看不到该份回答对应的账号，后台仍保留账号引用，用于防重和人数统计。用户可以关闭问卷，或设置、延长、清除截止时间。发布后的题目与填写设置冻结，关闭后不可重新开放；到期通过当前时间计算，不另存一个 `expired` 状态。

第一阶段不提供账号改名、账号删除、问卷删除、发布后修改题意、跨页面恢复未提交草稿或实时统计推送。应用和 MongoDB 均在本机运行；不据此声称公网部署已经验证。

## 2. 为什么这样组织文档

教材第 3.1 节从“存什么、怎么存、如何访问”分析数据库设计，第 3.2 节比较分别存储、嵌套存储与适当冗余。本项目据此以实际读写边界划分文档。

编辑和填写问卷时需要一次取得有序题目、选项、约束及跳转规则，因此把这些配置嵌入一份问卷。保存草稿时一次更新完整配置，避免先写题目、后写规则造成中间状态。每份提交也作为一份完整答卷写入，其中嵌入本次经过的路径和答案。

答卷数量会持续增加，若把所有答卷嵌入问卷，每次填写都会修改同一文档，文档也会不断膨胀。因此问卷与答卷分开存储，通过 `survey_id` 关联。用户独立存在，问卷引用创建者，答卷引用填写者；不在每份答卷复制用户名、密码或完整题干。会话独立存储，便于撤销和到期清理。

关系数据库也能实现本系统。这里采用 MongoDB 是课程要求，同时嵌套数组能直接表达一份问卷的题目顺序、不同题型的配置以及一份完整答案。若将题目、选项、约束和规则逐层拆为关系表，读取问卷时需要重新组装；本项目选择按问卷整体读写。代价是更新一个题目也保存整份草稿，且跨文档引用完整性主要由应用保证。没有进行不同数据库模型的性能对照实验，因此不宣称该组织方式在所有场景下更快。

`path` 是有意保留的少量冗余：它区分“经过但空答”与“因跳转未访问”。`repeat_allowed` 复制冻结的问卷设置，用于部分唯一索引。二者均由后端产生，不接受客户端直接赋值。

## 3. 集合与字段字典

实际集合统一使用 `survey_` 前缀，不占用课程实验的 `users` 集合。下面的 `ObjectId`、`Date`、`Decimal128` 是 BSON 类型。每份顶层文档共有 `_id: ObjectId` 和 `schema_version: int = 1`；其余字段如下，明确标注可空的字段才允许 `null`。

### 3.1 `survey_users`

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `username` | string | 去首尾空白并转小写；3—32 个字符，允许基本汉字、英文字母、数字和下划线；唯一 |
| `password_hash` | string | pwdlib 推荐配置产生的 Argon2 密码哈希；不存明文密码 |
| `created_at` | Date | 服务器记录的注册时间 |

注册密码为 8—128 个 Unicode 码点，不自动去首尾空白。用户名校验范围以 `app/main.py` 的正则为准，中文字符范围为 U+4E00—U+9FFF。

### 3.2 `survey_sessions`

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `user_id` | ObjectId | 引用 `survey_users._id` |
| `token_hash` | string | 随机会话令牌的 SHA-256；原令牌只发送给浏览器 cookie |
| `created_at` | Date | 登录创建时间 |
| `expires_at` | Date | 创建后 24 小时；应用校验及 TTL 清理依据 |

cookie 为 `HttpOnly`、`SameSite=Lax`、`Path=/`。本机 HTTP 配置允许 `Secure=false`；使用 HTTPS 时配置为 `true`。退出删除当前会话，重新登录撤销当前 cookie 对应的旧会话并生成新令牌。TTL 删除存在延迟，应用每次认证仍检查 `expires_at`。

### 3.3 `survey_surveys`

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `owner_id` | ObjectId | 创建者引用，管理查询同时按此字段过滤 |
| `title`、`description` | string | 标题、说明；上限分别为 200、5000 码点 |
| `allow_anonymous` | bool | 是否允许填写者选择匿名，默认 false |
| `allow_repeat` | bool | 是否允许同一账号有意填写多份，默认 false |
| `state` | string | `draft`、`published`、`closed` |
| `deadline_at` | Date 或 null | 截止时刻；null 表示不设截止 |
| `revision` | int | 从 1 开始，成功管理更新加 1；最大 2147483647 |
| `content_version` | int 或 null | 草稿为 null，首次发布后为 1，固定该答卷对应的题意 |
| `created_at`、`updated_at` | Date | 创建时间、最后成功管理更新时间 |
| `published_at`、`closed_at` | Date 或 null | 尚未发生对应状态变化时为 null |
| `questions` | array | 按显示顺序嵌入题目，不另存位置字段；最多 100 题 |

题目共同字段：

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `id` | UUID string | 整份问卷内唯一；修改文字或顺序时保留 |
| `kind` | string | `single`、`multiple`、`text`、`number` |
| `title` | string | 题干，最多 1000 码点；发布时去首尾空白后不得为空 |
| `required` | bool | 是否必答；只约束实际到达的题目 |
| `validation` | object | 题型对应的约束，见下表 |
| `options` | array | 单选、多选选项；其他题型为空数组 |
| `rules` | array | 按优先顺序保存规则，最多 50 条；文本题为空数组 |

| 题型 | `validation` 字段 | `options` 与规则 |
|---|---|---|
| single | 空对象 `{}` | 至少两个选项；规则 `eq`，operand 为一个选项 ID |
| multiple | `min_choices`、`max_choices`：非负整数或 null | 至少两个选项；规则 `any/all/exact`，operand 为非空且无重复的选项 ID 数组 |
| text | `min_length`、`max_length`：非负整数或 null | 无选项、无规则；非空答案 trim 后按 Unicode 码点计长度 |
| number | `min_value`、`max_value`：Decimal128 或 null；`integer_only`：bool | 无选项；规则 `eq/ne/gt/gte/lt/lte`，operand 为 Decimal128 |

选项为 `{id: UUID字符串, text: string}`，ID 在所属题内唯一，每题最多 100 项，每项文字最多 200 码点。规则为 `{op, operand, target}`；`target` 是后续题目的 ID 或 `END`。发布检查阻止向前或不存在的目标；草稿可以暂时保留未配置完整的业务内容，便于继续编辑。

### 3.4 `survey_responses`

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `survey_id` | ObjectId | 引用问卷 |
| `respondent_id` | ObjectId | 引用填写者；匿名时后台仍保留 |
| `content_version` | int = 1 | 本份答卷使用的冻结题意版本 |
| `anonymous` | bool | 本次填写是否匿名，由服务端核对问卷设置 |
| `repeat_allowed` | bool | 从发布后的问卷复制，不能由客户端指定 |
| `submission_key` | UUID string | 一次有意填写的标识；结果未知时使用原键重试 |
| `request_digest` | string | 版本、匿名选择、规范化答案的 SHA-256 |
| `accepted_at` | Date | 最后读取问卷并检查提交资格时的服务器时间 |
| `created_at` | Date | 准备插入答卷的时间 |
| `path` | UUID string array | 实际经过的题目，含明确空答题；由服务端重放产生 |
| `answers` | object array | 每项为 `{question_id, value}`，只保留路径上的非空答案 |

`value` 按题型分别是单选选项 ID、多选选项 ID 数组、trim 后文本、Decimal128。数字 0 是有效答案。未访问题与已访问空答均不进入 `answers`，通过 `path` 区分。

### 3.5 文档示例

下面是用于说明 BSON 类型与嵌套方式的 Extended JSON 结构示例，ID 和时间均为示意值，不是测试执行输出。它表示已发布的一题数字问卷；完整四题型与答卷样本由基线封存文件保存。

```json
{
  "_id": {"$oid": "670000000000000000000001"},
  "schema_version": 1,
  "owner_id": {"$oid": "670000000000000000000002"},
  "title": "年龄调查",
  "description": "填写年龄，也可以跳过",
  "allow_anonymous": true,
  "allow_repeat": false,
  "state": "published",
  "deadline_at": null,
  "revision": 3,
  "content_version": 1,
  "created_at": {"$date": "2026-10-16T02:00:00.000Z"},
  "updated_at": {"$date": "2026-10-16T02:02:00.000Z"},
  "published_at": {"$date": "2026-10-16T02:02:00.000Z"},
  "closed_at": null,
  "questions": [{
    "id": "00000000-0000-0000-0000-000000000001",
    "kind": "number",
    "title": "年龄",
    "required": false,
    "validation": {
      "min_value": {"$numberDecimal": "0"},
      "max_value": {"$numberDecimal": "120"},
      "integer_only": true
    },
    "options": [],
    "rules": [{"op": "gte", "operand": {"$numberDecimal": "18"}, "target": "END"}]
  }]
}
```

## 4. 七个显式索引与初始化

每个集合还具有 MongoDB 默认 `_id` 索引，下表不重复计入。

| 集合 | 索引名 | 键及选项 | 用途 |
|---|---|---|---|
| survey_users | `username_unique` | `username:1`，unique | 并发注册时拒绝同名账号 |
| survey_surveys | `owner_created` | `owner_id:1, created_at:-1, _id:-1` | 个人问卷列表及稳定排序 |
| survey_sessions | `token_unique` | `token_hash:1`，unique | 会话定位及令牌唯一性 |
| survey_sessions | `session_expiry` | `expires_at:1`，TTL=0 | 清理已到期会话 |
| survey_responses | `submission_unique` | `survey_id:1, respondent_id:1, submission_key:1`，unique | 同一次提交重试只保存一份 |
| survey_responses | `once_per_account` | `survey_id:1, respondent_id:1`，unique，partial=`{repeat_allowed:false}` | 禁止重复问卷每账号最多一份 |
| survey_responses | `survey_created` | `survey_id:1, created_at:-1, _id:-1` | 按问卷查询及内容分页 |

启动先连接 MongoDB，创建缺失集合和索引，再核对 validator 与索引规格。validator 使用 `validationLevel=strict`、`validationAction=error`，检查关键 BSON 类型、必填字段和枚举；嵌套配置的业务合法性仍由后端模型及领域层负责，validator 不是完整业务规则引擎。已有 validator 不匹配、索引规格冲突或存在未知 `schema_version` 时启动失败，不自动覆盖原契约。`/health` 复核连接、validator 和索引；未知版本检查在初始化阶段执行。

## 5. 第一阶段保留给第二阶段的内容

保留问卷、题目、选项的稳定标识，区分 `schema_version`、`content_version` 与管理 `revision`。基线样本覆盖四题型、空答、匿名、重复及分支，后续修改须继续验证旧题意、路径、统计和数据可读性。

如果第二阶段要求发布后修改题目，可以再引入不可变题意版本并迁移现有版本 1；当前没有提前实现该功能。任何迁移都需要保留旧数据，核对迁移前后数量和统计，并继续运行旧样本。最终封存内容与状态见交付清单及验收证据，不以设计说明替代实际封存结果。
