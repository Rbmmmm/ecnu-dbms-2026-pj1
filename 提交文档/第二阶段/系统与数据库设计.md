# 第二阶段系统与数据库设计

适用代码：`c1a65d18b8066868195078422801e1070d3c87b2`。本文说明第二阶段设计；第一阶段说明保留在上一级目录。运行与授权接口见[运行与API说明](运行与API说明.md)，机制见[关键逻辑](关键逻辑说明.md)。

## 1. 系统边界

沿用FastAPI、PyMongo、Jinja2、原生JavaScript，业务数据全部存MongoDB。原问卷的发布、填写、路径重放、最终提交和单卷统计保留；新增题目管理、版本历史、共享使用、个人题库及授权跨卷统计。没有团队共同编辑、全站公开结果或一键把旧卷题目回填为历史来源的功能。

领域逻辑在`app/domain.py`，原统计在`app/statistics.py`，十进制在`app/decimal_values.py`；新增`app/question_catalog.py`管理题目来源，`app/question_statistics.py`管理跨卷统计。`app/main.py`整合路由与权限，`app/db.py`定义结构、索引和启动检查。

## 2. 标识与版本

| 字段 | 含义与类型 | 不应混用的对象 |
|---|---|---|
| question_id | 题目家族ObjectId | 不等于答卷answers.question_id |
| question_version_id | 某个定稿/草稿版本ObjectId | 不等于问卷content_version |
| questions[].id | 本卷实例UUID | rules.target、path、answers.question_id均引用它 |
| options[].id | 版本/实例语境内选项UUID | 相同选项文字或ID不能跨版本自动合并 |
| schema_version | 文档存储形状 | 不代表题意版本 |
| content_version | 本卷发布内容标记，draft为null、发布1 | 不用于家族历史排序 |
| revision | 单文档管理并发编号 | 修改必须与已读值及CAS均匹配 |
| version_no | 家族内展示序号 | 可间断，父子关系看parent_version_id |

## 3. 七集合

| 集合 | 主要字段 | 数据边界 |
|---|---|---|
| survey_users | username、password_hash、created_at | 用户名唯一，密码不存明文 |
| survey_sessions | token_hash、user_id、expires_at | TTL会话；令牌原文不持久化 |
| survey_surveys | owner_id、state、questions、revision、content_version、截止/匿名/重复设置 | questions完整嵌入，发布冻结；schema2增加来源与grant |
| survey_responses | survey_id、respondent_id、anonymous、submission_key、request_digest、accepted_at、path、answers | 一次提交一文档，answers仅非空值，path保留空答题 |
| survey_questions | owner_id、label、shared_with、revision、creation_key、creation_digest | 家族负责组织和共享，label不是题干；最多100名共享者 |
| survey_question_versions | question_id、version_no、state、revision、parent_version_id、operation、restored_from_version_id、payload、payload_hash、sealed_at及创建幂等字段 | 每版本独立文档；sealed不改写，不硬删除 |
| survey_question_banks | owner_id、title、revision、entries及创建幂等字段 | 个人题库；同家族一条，最多1000条；default_version_id明确选版 |

新三个集合的schema_version为1。原users/sessions/responses仍为1；新原生问卷也为1，首次导入来源题时同次CAS升为2。旧发布问卷和旧答卷零回填。

版本payload仅含kind/title/required/validation/options，rules只在问卷实例。source含question_id、question_version_id、payload_hash；hash用于完整性，不能替代版本身份。schema2的question_result_grants按家族保存enabled与allowed_at_publish；受益人从题目家族解析，不由客户端指定。schema1明确拒绝source/grant两个保留字段。

恢复旧版创建另一draft，operation=restore，parent与restored_from均为目标sealed版；定稿后独立计为新版本。派生operation=derive，parent为来源sealed版、restored_from为null。默认版本更新不追溯改变任何实例。

## 4. 嵌入、引用和冗余

问卷配置整体读取与保存，适合嵌入题目、选项及规则；答卷不断增长，独立集合便于按卷查询并一次写入完整结果。家族引用独立版本，避免历史无界扩张单一文档。题库内嵌有上限的成员。

采用“独立版本＋问卷完整副本”，导入/换版时复制并校验来源；已发布卷不依赖当前共享状态或题库默认版。纯版本引用会扩大旧填写路径改造，单纯复制又无法可靠汇总。同名题和同hash版本不自动等同。使用关系直接反查问卷source，不建立需双写维护的关系集合或结果计数器。

关系数据库也能实现本系统。这里依据课程要求及整体读取边界选择MongoDB，不以无依据的性能优势解释选择。教材参考课程根目录`教材/onlineDBMSbook/chapter3.1.md`及`chapter3.2.md`。

## 5. 索引与数据库约束

共16个显式索引，另有7个默认_id索引。原7个显式索引保持：用户名唯一、会话令牌摘要唯一与TTL、问卷归属列表、答卷列表、提交键唯一、禁止重复时按账号部分唯一。

新增9个：

| 集合 | 索引键（顺序） | 作用 |
|---|---|---|
| questions | owner_id / created_at↓ / _id↓ | 本人列表 |
| questions | shared_with / created_at↓ / _id↓ | 获共享列表 |
| questions | owner_id / creation_key，唯一 | 创建恢复 |
| question_versions | question_id / version_no，唯一 | 历史及并发序号 |
| question_versions | question_id / creation_key，唯一 | 同次创建不重复 |
| question_banks | owner_id / created_at↓ / _id↓ | 本人题库列表 |
| question_banks | owner_id / creation_key，唯一 | 创建恢复 |
| surveys | questions.source.question_id | 家族使用查询 |
| surveys | questions.source.question_version_id | 确切版本引用查询 |

应用校验同文档数组唯一，不依靠unique多键索引约束数组内部重复；组合来源条件保持在同一实例，避免跨元素匹配。validator使用strict/error，不因升级失败降成warn。应用负责跨文档来源、权限与状态检查。

请求1 MiB、文档8 MiB保护线；revision/version_no最多2147483647。版本序号分配与插入总共最多尝试5次，持续冲突则返回409，不复用历史序号。

## 6. 权限与访问路径

| 对象 | 规则 |
|---|---|
| 编辑、定稿、派生、恢复、共享 | 仅题主 |
| 新导入、换版、题库新增或改默认版 | 当前题主或获使用权者，且确切版sealed |
| 使用清单 | 题主全部引用，其他使用者仅本人；只给卷ID/标题/状态/expired及各版实例数 |
| 跨卷汇总 | 题主本人及有效授权卷；其他使用者本人卷 |
| 原管理、整卷/实例统计、原文 | 始终仅卷主 |

先确定允许published/closed卷及实例（含到期卷），再读答卷；draft仅使用清单。返回前复核全部外部grant所在survey.revision，每100卷分批，变化409。最终核对后允许已受理响应完成，后续排除撤权卷；不保证事务快照。

共享撤回不毁旧快照。已引用者只可从本人实例读取确切来源，不得遍历无权家族历史。结果授权在草稿按家族设置，默认关，发布冻结上限；发布后只可撤回且不可重开。题库移除、使用撤回和结果撤回互不替代。

## 7. 兼容升级

完全无survey_集合时初始化七集合；已有任何survey_集合时严格检查，不自动修补或迁移。显式升级CLI仅支持本机隔离副本，见运行说明。原版schema/API严格恢复仍在3645b07执行；新版以明确允许差异核对原字段、ID、题意、path、答案、原统计及权限。

允许差异：新三集合及上述索引；surveys双分支validator与来源索引；Question可选source；新专用路由；schema2管理source/grant/result_grant_options、填写result_sharing_notice；health的实现阶段与契约2。原生schema1的响应不加source:null。原三永久集合逐字段保护，会话仅允许有时间依据的TTL自然删除。业务库仍v1，未执行迁移。
