# 问卷系统测试用例与结果

以下结果来自 2026 年 10 月 16 日、10 月 22 日的真实执行，使用 Python 3.11.17、MongoDB Community 8.0.32 和 Chromium。10 月 22 日在独立 Python 环境中按锁文件安装依赖后，101 个 API/真实数据库参数案例全部通过，0 失败、0 错误、0 跳过；四套网页流程、应用重启及 v1 新建和恢复也通过。各项结果的执行日期和原始输出见文末证据表，同一批案例的重复执行不计作新增用例。

测试使用独立的 `survey_test_<run_id>` 数据库，结束后清理，不使用业务 `.env` 中的数据库。唯一索引、validator、并发写入和统计均使用真实 MongoDB。重启验证只停止并重启应用进程，没有重启 MongoDB 服务或整台电脑。

## 六类必测功能

下列预期来自需求与已确认规则。实际结果由运行报告、JUnit、网页记录和数据库断言共同核对，未将“已收集测试”计为通过。

### 创建问卷

步骤：注册并登录 U1，创建标题为 S、允许匿名的问卷；查询本人的管理列表与详情。再以 U2 请求同一管理地址和列表。

输入：创建 JSON 中 `title="S"`、`allow_anonymous=true`；管理路径使用创建响应中的真实 ID。

预期：创建 201，草稿 revision=1，owner_id 指向 U1；U1 可见，U2 列表不含 S，直接管理请求 404。

实际与结果：`test_T01_ownership_and_app_restart` 与列表/归属案例通过。新增 23 份 API 样本、22 份网页样本的稳定分页没有漏项或他人问卷。新封存流程也经真实 HTTP 创建三份问卷并保存到 MongoDB。

### 添加与编辑题目

步骤：创建草稿，保存题目、选项和约束，读取回验 ID 与内容；用同一个旧 revision 再提交修改；发布后再次修改题目。

输入：F01 的 single、multiple、text、number 四题；多选限制 1—2 项，文本 1—10 码点，数字整数 0—120。

预期：合法保存后 revision 增加，稳定题目/选项 ID 不变；过期修改和发布后编辑返回 409。未完成但结构合法的草稿可以保存，不能发布。

实际与结果：T02 系列及同 revision 并发测试通过；两个并发更新为一项 200、一项 409，MongoDB 中整份内容属于胜出请求，没有拼接出两份配置。封存问卷读取与输入一致。

### 跳转逻辑

步骤：发布 F02；先走 J1=A、J3=18、J5=null，再走 J1=B、J2=[x,y]、J4=“完成”、J5=null。网页回退 J3=17，补答 J4，再将 J1 改为结束。

预期：第一份路径 `[J1,J3,J5]`，非空答案 2 个；第二份 `[J1,J2,J4,J5]`，非空答案 3 个。多条规则命中时，规则数组中排在前面的优先；18 改 17 后 J4 必须补答，J5 暂存后可复用；END 清空后续缓存并等待明确提交。

实际与结果：T03、F02 网页及新封存样本均符合上述路径。END 不会自动保存，已删除分支不再复活。更换全部题目/选项 ID 与文字后仍通过，说明流程没有依赖某份问卷的固定编号。

### 答案校验

步骤：直接调用 API，绕过页面输入限制，分别提交边界与非法答案；检查状态、定位错误及答卷数量。

输入：恰好选 2 项时给 1/2/3 项；文本 `"  中文 A  "`；整数题给 `"18.0"`、`"18.5"`；范围 0—120 给 `"0"`、`"120"`、`"-1"`、`"121"`；数字 NaN、Infinity、不可无损表示值；重复或未知选项。

预期：只有合法值通过；文本规范为“中文 A”，长度 4；18.0 为整数，18.5 拒绝；0 有效而非空答；端点通过、越界拒绝；错误不能增加答卷。evaluate 的题目业务错误为 200+errors，结构错误和非法提交为 422，二者不可混为一谈。

实际与结果：T04/T13 全部通过。同时检查 revision 超过 `2**31-1` 或 offset 超过 `2**63-1` 时返回 422；版本已到最大值的管理更新返回 409。超大整数异常与其修复见[真实修复记录](附件/P4-真实修复记录.json)。

### 提交问卷

步骤：登录，回答到确认页，确认前读取答卷数量；点击提交后再读；用原 submission_key 和相同内容重试，然后改内容或在禁止重复问卷中使用新 key。

输入：一份明确空答的合法问卷、一份正常问卷，以及同 key 同内容/改内容请求。并发场景使用 10 个独立账号会话。

预期：确认页不保存；首次成功 201；同 key 同内容 200 原收据且只有一条记录；改内容或违反每账号一次限制为 409。10 个账号各保存完整答卷；写入后响应丢失可以凭原 key 恢复。

实际与结果：T05/T09、网页响应截断恢复和新封存重试全部通过。8 份封存答卷中包含 F01 全空答卷及禁止重复问卷的全空答卷；后者第二个 key 返回 `ALREADY_SUBMITTED`，数量没有增加。T10 验证已通过最后受理检查的在途请求可以在关闭后完成，关闭之后才受理的新请求拒绝。

## 真实缺陷与回归

2026 年 10 月 16 日的检查发现，`1E34、1、-1E34` 六种排列中四种均值错误显示为 0.00；改用精确累加后全部显示 0.33。另四个正负双重舍入案例原本显示 ±1.01，改为直接根据精确总和与计数保留两位后得到 ±1.00。超大 revision/offset 曾返回 500，发布接口曾返回 409；补齐各自上界校验后，七种超界请求均返回 422，已达版本上限的管理更新仍返回 409。

网页检查还发现，70 码点表情密码被截为 64 码点，匿名选择在回退后变为实名。修复后，合法密码可完整注册登录，匿名选择在同一次填写中保留，并与实际答卷及内容接口核对。上述失败输入、修复和回归结果见[真实修复记录](附件/P4-真实修复记录.json)。

## 复现命令

先按[运行与 API 说明](运行与API说明.md)安装锁定依赖，准备本机 `127.0.0.1:27017` 的 MongoDB；网页测试还需按根 README 准备 Node.js、Playwright 和 Chromium。在项目根目录执行：

```bash
python -m pytest tests/test_p2.py tests/test_w007.py tests/test_w008.py tests/test_p4.py -o addopts= -q
python scripts/test_browser.py
python scripts/v1_baseline.py --output artifacts/v1-check
python scripts/v1_baseline.py --restore 提交文档/附件/v1-baseline.json --output artifacts/v1-restore
```

每个 v1 输出目录须尚不存在。网页入口运行四套脚本，检查应用重启前后四集合 BSON 摘要，并清理隔离数据库；v1 入口核对样本的新建、恢复和重启读取。测试不依赖业务连接、内部审核或映射文件。
