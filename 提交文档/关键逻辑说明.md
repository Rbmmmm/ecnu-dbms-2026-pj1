# 关键逻辑说明

本系统把问卷配置、答案校验和跳转计算放在后端，页面通过同一套评估接口获得当前路径。本文说明实际代码中的判断顺序、数据含义和并发边界；示例用于解释算法，实际测试结果另见测试证据。

## 1. 草稿、发布与版本

保存草稿首先检查字段类型、UUID 格式与唯一性、十进制表示和工程上限。空题干、未完成的选项或暂时失效的跳转目标可以保留，响应同时给出 `publish_issues`，以便继续编辑。

发布时再检查完整业务配置：标题和题干非空，选择题至少包含两个文字不同的非空选项，上下限不矛盾且允许至少一种非空合法回答；设置整数限制的数字区间必须包含整数。规则操作符须符合题型，目标只能是后续题或 `END`；文本题不能配置跳转，填空题不能保留选项。只允许向后跳转，也就排除了循环。

每次管理更新使用 `_id + owner_id + state + revision` 作为条件，成功后 revision 加 1。两个窗口都基于 revision=2 保存时，只有一个能够更新，另一个收到 409，不会静默覆盖。发布检查使用当前读取的配置，真正状态更新还必须命中该 revision。已发布再次发布、已关闭再次关闭可以返回当前状态，但不能借此修改题意。

`schema_version=1` 表示存储解释方式；`content_version=1` 表示发布后冻结的题意；revision 只是管理修改序号。当前请求只接受整数内容版本 1；第二阶段若增加内容版本，需要相应扩展校验与读取逻辑。

## 2. 答案规范化与校验

输入是 `answers={题目ID:值}`。缺少 key 表示还未确认该题；值为 null 表示明确跳过非必答题。空文本和空多选数组规范化为 null，数字 0 不为空。

| 题型 | 规范化 | 业务校验 |
|---|---|---|
| 单选 | 保留所属选项 ID | 必答时非空；选项必须存在 |
| 多选 | 拒绝重复或未知选项，按题目选项顺序排列 | 必答、最少/最多选择数；同一答案不重复计选项 |
| 文本 | 去首尾空白 | 按 Unicode 码点检查长度；工程上限 10000 |
| 数字 | 严格解析十进制字符串，确认能无损存为 Decimal128，移除无意义尾零 | 整数、最小值、最大值；18.0 是整数，NaN、Infinity 和溢出拒绝 |

输入结构检查覆盖请求中的题目与答案，未知题 ID、错误类型或重复多选 ID 会立即拒绝。随后仅对当前有效路径执行必答和业务范围校验。因此合法结构的旧分支答案即使不满足该题范围，也不会阻塞已经跳过它的新路径；结构非法的请求仍须先修正。

## 3. 规则匹配与路径重放

规则保存为 `{op,operand,target}`。单选仅支持 eq；多选支持 any（有交集）、all（包含规则集合）、exact（集合相等）；数字支持 eq、ne、gt、gte、lt、lte。多选 exact 不受选项数组顺序影响。null 不匹配任何规则，包括数字 ne，直接走默认下一题。

重放从第一题开始，将到达的题加入 path。该题缺 key 时停留；有答案但校验不通过时停留并返回定位错误；合法时按 rules 数组顺序使用第一条命中规则，没有命中则进入下一题。到 END 或末题后只设置 `ready_to_submit=true`，不会自动保存答卷。

例如，某多选题的规则依次为 `any[x]→J4`、`all[x,y]→J5`，回答 `[x,y]` 同时满足两条，但应到 J4。规则顺序是配置的一部分，不从题号、文字或某个样本常量推导跳转。

后端返回：`path`、`active_answers`、`pending_answers`、`removed_question_ids`、`current_question_id`、`ready_to_submit` 和 `errors`。active_answers 保存已经确认的有效答案，包括 null；path 末尾可以是正在等待回答的题目，不能将“到达”理解为“已经完成”。

## 4. 回退时为什么需要 pending

回退只能选择已到达的题目。修改旧答案后，后端从第一题重新计算，明确跳过的题立即从缓存删除；以后再次进入该分支，也不能恢复已经删除的旧答案。

但“暂时无法判断后续路径”与“已经确定跳过”不同。例如原路径为 `[J1,J2,J3,J5]`，J5 已填“保留”；把 J1 改为直接去 J3 后，应删除 J2，但继续保留仍可达的 J3、J5。再把 J3 从 18 改为 17，路径先转到尚未回答的必答 J4，暂时无法确认后续是否仍到 J5。此时 J5 只能进入 pending；填完 J4 后，如果规则到达 J5，就复用其合法答案。如果跳过 J5，则删除。

pending 只存在浏览器当前页面的内存中，不是服务器草稿，不显示为已完成，不计入统计，也不能直接提交。到 END 时后续缓存全部删除；返回其他分支后必须重新回答已删除的内容。

浏览器为评估请求编号，旧请求晚到的成功或失败结果均丢弃，防止较旧路径覆盖新输入。当前题的非法原输入保留在表单中供修改；不能因为评估有 errors 就把用户输入全部清空。

## 5. 确认、提交、防重与重试

提交时后端再次完整重放，不能信任前端已经显示确认页。必须到达结束且无错误，answers 的 key 集合还必须恰好等于最终 path。缺少路径内空答 key，或混入已跳过分支的答案，均返回 422；客户端传入 path、respondent_id 等额外字段也被模型拒绝。

规范化结果用于计算 SHA-256 摘要，摘要对象包含内容版本、匿名选择和当前有效答案。单选 ID、多选顺序、文本空白和等值数字先统一，因此数字 `18` 与 `18.0` 不会仅因表示不同被认定为不同内容。

一次有意填写使用一个随机 submission_key。后端查找 `survey_id + respondent_id + submission_key`：已有同摘要记录就返回原收据，摘要不同则 409。没有旧记录时才检查接收资格并一次插入完整答卷。`path` 保留显式空答题的 ID，对应的 `null` 不写入 `answers` 数组，因此保存的答卷既能解释经过的路径，也只包含实际非空答案。

并发请求可能同时查不到旧记录，所以查询不是最终防线。`submission_unique` 确保相同键只能落库一次；`once_per_account` 在禁止重复时确保同账号不同键也只能一份。插入发生唯一冲突后，先重新查原键，能找到就比较摘要并恢复收据；否则命中禁止重复条件则返回 `ALREADY_SUBMITTED`。其他数据库异常不能一律解释成重复提交。

数据库写入可能已成功，但网络响应丢失。此时 API 不猜测成功，页面保留原键与冻结内容重试；重试若找到已成功记录，则返回 200 原收据，无新增。明确校验失败后可以修改内容继续使用尚未成功的键。提交结果未知时不能换键试探，否则允许重复的问卷可能真的产生第二份答卷。成功后的“再填一份”才清空表单并生成新键。

## 6. 截止、关闭与在途请求

在确认没有成功旧记录后，提交再次读取当前问卷，记录服务器受理时间。仅 `published` 且未到截止时允许接收；`accepted_at >= deadline_at` 即拒绝。创建者修改截止、关闭问卷也使用 revision 条件更新。

问卷状态检查与答卷插入跨集合，当前没有事务。系统明确允许已经通过最后接收检查的在途请求完成：某请求检查时开放，随后创建者关闭，再恢复该请求插入，仍然可以成功；关闭后才进行接收检查的新请求则拒绝。已经成功的原键重试放在资格检查之前，所以关闭或到期后仍能取回原收据。

这项设计以最后一次接收检查划分新请求和在途请求，避免为本机单实例运行引入跨集合事务。代价是关闭操作完成后，先前已受理的答卷仍可能落库。若下一阶段要求同时阻断这些写入，需要重新设计事务或串行接收机制，并继续验证原有行为。

## 7. 统计口径与数值计算

统计从 MongoDB 中已经保存的答卷计算，不维护需要同步更新的计数器。先检查问卷归属，再按 survey_id 筛选。整卷和单题 API 复用同一统计函数，单题结果取自相同口径。

| 统计对象 | 计算方式 |
|---|---|
| 整卷次数 | 答卷文档数量；合法全空答卷也算一次 |
| 整卷人数 | respondent_id 去重数量，匿名仍参与内部去重 |
| 单选每项人数 | 按题目、选项、账号分组去重 |
| 单选题目人数 | 按题目、账号去重；同一人多次选不同项仍是一人 |
| 单选次数 | 每份非空单选答案计一次，另给每选项次数 |
| 多选次数 | 展开各答案数组，按选项计出现次数 |
| 文本/数字内容 | 只查询 answers 中存在的非空内容，按时间及 `_id` 倒序分页 |
| 数字均值 | 只使用实际数值答案，含 0，排除空答与未访问题 |

例如同一账号先选 A 后选 B，会给 A、B 各贡献一人，但题目总人数仍为一人；所以选项人数之和可以大于题目人数。显示所有选项时先按配置初始化 0，再合并统计，确保未被选择的选项也可见。匿名内容只输出 value、created_at、anonymous；实名条目另有 username，后台去重账号集合不会发送给创建者。

数字不能通过 JavaScript Number 或二进制浮点中转。后端从 MongoDB 流式读取 Decimal128，转换成 Decimal 并以足够精度精确累加；API `average` 在 Decimal128 精度下进行除法，`average_display` 直接根据精确总和与计数的分数进行一次 ROUND_HALF_UP 两位舍入。它不对已近似的 average 再舍入，避免二次舍入跨过半分边界。没有有效数字时 average 为 null，页面显示“暂无数据”。

采用精确累加和一次显示舍入，是为了修复测试中发现的有限消去与双重舍入问题，包括 `1E34,1,-1E34` 的均值误差。具体失败输入与回归结果见《项目完成报告》第 7 节及《测试用例与结果》。每个数字题因此增加一次查询。并发提交期间，不同查询可能读到不同时刻的数据；目前没有跨查询快照，也未进行性能对照实验。

## 8. 数据与安全边界

管理查询同时过滤 owner_id；前端隐藏按钮不能替代后端权限。全部写请求核对 Origin、自定义请求头和 JSON 类型。模板与 JavaScript 按文本显示用户内容，登录回跳只接受本站路径。密码、会话原令牌和 Mongo URI 不进入响应；匿名隐私依靠响应字段白名单，不仅是在表格里隐藏某一列。

初始化检查未知 schema_version、validator 和索引。测试与 v1 恢复使用严格校验的本轮隔离数据库，不复用业务库，不对课程实验数据执行清理。封存样本与回归结果用于第二阶段验证旧行为。
