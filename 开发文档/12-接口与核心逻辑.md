# 接口与核心逻辑

依据B-001—B-016及[数据设计](11-数据与架构设计.md)，记录当前P4接口与核心逻辑。契约于2026-10-15形成，基础业务通过[P3验收](证据/P3-验收.md)，W-009边界修正及独立检查通过[P4验收](证据/P4-验收.md)；下方P2/W007补记仅描述当时范围。后续调整须同步本页与测试，常规工作无需新增审批环节。

## API共同约定

前缀`/api/v1`。ObjectId对外为24位十六进制字符串，UUID为标准字符串；时间带时区，数字题数值使用十进制字符串。请求未知字段拒绝；身份、归属、状态、实际版本及created_at等服务端维护字段不可由客户端任意改写；相关管理写操作传入revision、填写请求传入content_version作为预期版本供服务端校验，不代表客户端可更新版本。deadline_at按管理接口允许设置。可空值使用JSON null，缺省与显式清空按各接口定义区分。

成功直接返回资源或明确结果；错误统一为`{error:{code,message,fields:[{question_id,field,message}]}}`。400用于请求格式错误，401未登录或会话失效，403请求源校验失败，404资源不存在或无管理权限，409状态/版本/重复冲突，413请求过大，422配置或答案非法，503数据库不可用。错误不包含堆栈或凭据。Pydantic默认错误也适配这一结构。evaluate的合法请求可以200返回题目级errors，便于保留输入；结构或ID非法仍422。草稿保存成功返回资源和publish_issues，不把未完成配置误报为可发布。

除注册、登录和幂等退出外，以下接口均需有效会话；退出即使会话已失效也清cookie并返回204。所有写请求仍按11中的同源JSON规则检查。列表统一`0<=offset<=9223372036854775807, limit=1..100`，默认20；按created_at降序、_id降序排序。offset分页足够第一阶段，新增数据期间翻页可能移动；每次完整查看需在数据静止时核对，不宣称快照分页。

| 方法与路径 | 输入 | 输出与关键约束 |
|---|---|---|
| POST /auth/register | username,password | 201账号公开字段；不自动登录；重名409 |
| POST /auth/login | username,password | 200当前用户并设置会话cookie；旧cookie若有效先撤销后换新 |
| GET /auth/me | 无 | 当前用户id、username |
| POST /auth/logout | 无 | 204，删除当前会话并清cookie；已退出也可204 |
| POST /surveys | title,description,allow_anonymous,allow_repeat,deadline_at | 201草稿，questions=[]、revision=1；未提供项用默认值 |
| GET /surveys | offset,limit | 仅自己的问卷摘要、total；不包含完整题目数组 |
| GET /surveys/{id} | 无 | 所有者完整管理视图及revision |
| PUT /surveys/{id}/draft | revision,title,description,allow_anonymous,allow_repeat,deadline_at,questions | 整体替换可编辑配置并返回新revision；只允许draft |
| POST /surveys/{id}/publish | revision | 检查完整配置，发布并返回链接、content_version、revision |
| PATCH /surveys/{id}/deadline | revision,deadline_at | 仅published；未来时间或null；更新revision；草稿在PUT中修改 |
| POST /surveys/{id}/close | revision | published→closed；返回状态及revision；已closed可返回当前状态 |
| GET /fill/{id} | 无 | 已发布题目、匿名/重复设置、accepting布尔值、版本及deadline_at；自己的already_submitted提示；draft404 |
| POST /fill/{id}/evaluate | content_version,answers | 无持久化；返回路径、清理结果、当前题、是否可进入确认页、题目错误 |
| POST /fill/{id}/responses | content_version,submission_key,anonymous,answers | 首次成功201收据；同内容重试200原收据；冲突409 |
| GET /surveys/{id}/statistics | 无 | 整卷答卷数、去重人数及各题统计摘要；仅创建者 |
| GET /surveys/{id}/questions/{qid}/statistics | 无 | 单题同口径统计；无此题404 |
| GET /surveys/{id}/questions/{qid}/contents | offset,limit | text或number题全部非空内容分页、total；实名用户名或匿名标记，数字显示规范数值；选择题422 |

收据仅含`response_id, survey_id, accepted_at`，不回显账号引用和整份答案。页面只提供本次收据，不新增所有用户答卷明细接口。匿名展示必须审查原始JSON，而非仅隐藏表格列。

GET /fill 对closed/到期问卷仍可返回公开配置及accepting=false（无单独reason字段；正式提交返回NOT_ACCEPTING），供已打开页面和成功重试识别；不能创建新答卷。evaluate不改变数据库、不构成提交受理，不保证稍后的提交仍开放。已经登录才能读取填写配置，登录后可回到原链接。

## 草稿与发布校验

草稿允许留空题干、未配完选项或规则目标暂时失效，但类型、ID、数字表示、工程上限必须合法。草稿保存返回待修复问题列表，不把这些问题当发布成功。deadline_at在写入时必须为未来时间或null，发布时再次检查不能带已经过去的截止。每次发布按保存的revision对完整配置检查：

1. 标题和至少一道题；题干及选项去首尾空白后非空，同题选项文本不能重复；每个选择题至少两个选项。
2. 非负长度/数量整数上下界，min≤max，多选max不大于选项数；配置允许至少一种非空有效回答。required多选不能max=0，整数数字区间必须包含整数，文本最大长度不能小于1。即使非必答也不保留“只能空答”的无意义题配置。
3. min/max未指定表示该方向不加业务限制，仍受工程上限约束。数字有限且可存储；integer_only的上下限可非整数，只要区间中存在整数。
4. 规则op适合当前题型，operand类型正确、选项存在、集合非空不重复；目标存在且位置严格大于源位置，或END。文本无规则。目标只能向后已足够排除循环；仍给出明确定位错误。
5. 问卷中不可达题不自动删去，多规则重叠也不一律报错，因为“第一条命中”是已定语义。页面可提示完全重复规则，但不伪造复杂逻辑可满足性证明。不能把没有人走到某题当作统计错误。

编辑页允许增删、上下移动题目/选项/规则，显示目标题标题但保存ID。不做拖拽编辑器。改顺序后如果跳转变成向前，发布校验负责拦截；保存草稿仍可继续修复。

## 答案表示与规范化

answers是`{题目ID: 值或null}`映射；缺少key表示尚未经过或尚未确认本题，null表示已显式跳过的非必答题。single为选项ID；multiple为ID数组；text为字符串；number为十进制字符串。

空字符串去空白后、空数组都规范成null；0不能规范成空。拒绝错误类型、未知题ID、未知选项和重复多选ID。规范化多选按题目选项顺序排序；文本去首尾空白；数字等值表示规范化（18与18.0同值），用于一致校验与摘要。`null`不能满足必答。只对当前有效路径上的回答做业务范围检查，不因已被跳过的旧分支答案违反约束而阻塞新路径。

后端文本用Python Unicode码点计数；前端可用Array.from(text).length做提示，但服务端是最终判定。首尾空白的细微字符差异以服务端规范化结果为准；浏览器不要自行以不同规则删除答案。

## 路径计算与回退

领域层提供规范化、单题校验、next_target、replay四类普通函数。规则存于数据，函数只识别通用操作符，不含某份问卷的题号或答案常量。

从第一题开始重放：

1. 将本题加入已到达path。不存在答案key时停在本题，等待用户选择/输入或显式跳过；不能把未答非必答题自动略过。
2. 本题答案非法时停下并给错误；合法空答直接走默认下一题，不匹配包括ne在内的任何规则。
3. 非空合法答案按rules数组顺序取第一条命中；没有命中则下一题。到END或题目末尾后进入确认页，不自动插入答卷。
4. 跳到后续题会确定跳过一段题，将这些题的缓存答案删除。到END时删去后续所有缓存。路径只用后端计算结果。

回退操作只允许页面中已经到达的题。修改已答题后，从首题重新评估；仍在新路径的合法答案复用，确定跳过的答案立即删除，今后再返回该分支也不能复活已删除内容。

需要区分“已不可达”和“暂时还不能判断”：重放在新分支一个尚未答题停住时，后面已缓存的答案未必不可达。evaluate返回`pending_answers`供当前页面暂存候选，不能显示为已完成、不能用于统计或直接提交；后续路径证明可达才复用，证明跳过便删除。此候选仅在页面内存，不是服务器草稿。这样既不会猜新分支的答案，也不会提前丢掉后来仍可达的有效答案。

evaluate返回`path`、`active_answers`、`pending_answers`、`removed_question_ids`、`current_question_id`、`ready_to_submit`及`errors`。active_answers包含已经确认的可达题，保留null作为空答标记；path最后可以是正在等待答案的题。非法当前输入仍留在表单供修改，不因errors清空。浏览器为请求编号，丢弃晚到的旧评估结果，防快速改答时旧路径覆盖新路径。

提交时必须重放至END；任何当前路径题缺key、必答空值或非法答案均422。已知但不在最终path上的额外答案也返回422 STALE_BRANCH_ANSWERS，要求页面重新评估和确认；不把混入的无效分支保存或悄悄算入统计。最终写入前把path中null从answers数组移除。客户端伪造ready、path或respondent_id等字段直接拒绝。

## 提交防重与失败恢复

提交顺序如下，所有持久字段由服务端组装：

1. 校验会话与请求结构，读取冻结问卷，核对content_version，重放最终路径并规范化内容。
2. 计算request_digest，查找`survey_id + respondent_id + submission_key`。已存在且摘要相同：返回原收据，即使已关闭/到期；摘要不同：409 KEY_REUSED_WITH_DIFFERENT_CONTENT。
3. 无旧记录时，最后读取当前问卷，核对published与截止，记录服务器受理时刻；校验匿名选项符合冻结设置。复制repeat_allowed，生成完整response，一次insert_one。
4. 唯一冲突时先重查相同submission_key，命中则按摘要返回原收据或键冲突；否则若命中每账号一次的约束，409 ALREADY_SUBMITTED。不能把所有数据库异常都当作重复提交。
5. 数据库不可达或写入结果未知时503，不凭猜测返回成功；浏览器保留相同key和本次内容重试。已有写入会在步骤2恢复，未写入则按当前开放状态处理。

一次有意填写从打开填写页开始生成key；提交中禁止继续编辑或换key。校验明确失败可改答案继续使用该key；网络结果未知先重试原内容，不能用新key试探。收到成功后，允许重复问卷提供“再填一份”，清空表单并生成新key；默认一次问卷显示已完成。同页重试有保证，刷新后不保证恢复未保存的key/输入，符合B-007；允许重复情况下刷新被视为一次新填写，页面需说明。

## 统计算法与输出

不维护增量计数器，查询持久responses，先按survey_id过滤。所有者校验先于任何聚合。统一统计服务被整卷、单题接口调用，避免两套口径；静止数据上两接口同题结果必须相同。

- 整卷：submission_count为答卷数量；respondent_count为不同respondent_id数量。全空但合法的答卷也算一次整卷填写。
- 单选：先按question_id、option_id、respondent_id去重计算每选项人数；按question_id、respondent_id去重计算题目回答总人数；另外按答案出现次数统计题目及选项submission_count。不同选项人数之和可以大于题目回答总人数。
- 多选：展开每份答案的选项数组，每个选项计出现次数；一份答案不允许重复选项。另可返回answered_submission_count，不能当人数标注。
- 文本与数字：只选answers中存在的非空内容。内容接口按答卷时间及_id倒序分页；数字内容同样可逐条查看，不能只有平均数。
- 数字：从实际MongoDB的Decimal128数字答案流式精确求和；API average保留Decimal128精度，average_display直接由精确总和/计数进行一次HALF_UP舍入，不从近似average再次舍入。count只算数值答案；未答不当0，0计入。输出`average: 十进制字符串或null`、`average_display: 两位字符串或“暂无数据”`及answered_submission_count。
- 输出先按完整题目及选项配置初始化0，再合并聚合结果，保证无人选择的选项仍可见。匿名用户只在内部去重；创建者输出不包含去重用账号集合。

整卷计数、单选/多选摘要由一次多facet聚合生成；每个数字题另做流式精确均值查询，内容分页另查。第一阶段无实时推送，无缓存失效系统；并发填写期间不同查询时刻可以看到不同数量，不宣称跨请求事务快照。验收在写入结束后查询并比较全部结果，刷新应看到新提交。

## 页面与最小操作流程

页面路由定为`/register`、`/login`、`/surveys`、`/surveys/{id}/edit`、`/surveys/{id}/manage`、`/survey/{id}`、`/surveys/{id}/statistics`，与API前缀分开。

- 注册/登录页：规则提示、通用错误、登录后返回原站内问卷链接。
- 我的问卷：创建入口、仅本人列表、草稿/接收中/已截止/已关闭状态及管理按钮。
- 编辑页：基本设置、题目类型/必答/约束、选项增删排序、规则顺序与目标；显式保存草稿、发布前错误定位。
- 管理页：分享链接、截止修改、关闭、统计入口；冻结配置只读。
- 填写页：登录后按题推进，显示错误、返回已访问题；匿名开关默认关闭；结束后显示最终路径答案确认并提交。
- 统计页：整卷人数/次数分开显示，按题展示选项0值、人数口径提示、填空内容分页、数字平均值与有效回答数。

前端不得因为按钮隐藏就省略后端权限/校验。P2先打通单选的完整网页流程，P3补齐其他配置和路径交互。保留键盘可操作表单、label与错误定位，不以界面装饰替代功能。

`app/main.py`实现上表auth、问卷创建/列表/管理、草稿/发布/关闭、fill/evaluate/提交和单选整卷/单题统计。截止时间可经创建/草稿API设置并在提交检查；独立PATCH deadline、内容分页、多题型和跳转尚未实现，P3补齐。页面当前不提供截止编辑，明确标注P3。P2 evaluate采用顺序单选重放，仍区分缺key与null，确认不落库；完整分支算法留W-007。未知API/方法使用统一error结构，请求非法JSON400、模型非法422；登录密码错误统一401。网络或响应解析失败保留冻结提交重试，已用响应截断实测。

## W-007实施补记（2026-10-15，历史范围）

全题型模型/约束及规则编辑、normalize/validate/next_target/replay已在schemas.py/domain.py/app.js落实。草稿保存结构类型合法的业务错误配置，发布返回定位问题；提交重放并拒绝旧分支额外答案。evaluate对结构错误422，对当前路径业务错误200 errors；即使有errors，页面应用已确定的清理并保留当前原输入。缺题处停止，后续仅pending，不进入确认或写库。前端回退使旧评估编号失效，评估期间禁止编辑字段，旧成功或失败结果均丢弃。文本输入不以HTML UTF16 maxlength替代码点边界。统计与内容分页/截止PATCH依旧待W-008。

## W-008实施补记（2026-10-15）

PATCH /surveys/{id}/deadline接收必填revision与deadline_at（未来带时区ISO或null），只更新published问卷的截止/updated_at/revision；过期可延长，closed/draft不允许，归属及revision CAS保持。管理页固定Asia/Shanghai转换，独立于浏览器本地时区。

statistics.py取代pending_W008：single保留原双计数字段；multiple返回answered_submission_count及每选项selection_count；text返回answered_submission_count；number另含average（十进制字符串或null）、average_display（两位或暂无数据）。整卷/单题共用服务。内容GET /surveys/{id}/questions/{qid}/contents仅text/number，offset>=0、limit1—100默认20；按created_at及_id降序。根字段question_id/kind/items/total/offset/limit；item直接白名单value/created_at/anonymous，只有实名再含username。匿名行不含账号、答卷ID、防重键或摘要；不把整份文档序列化后删字段。

页面文本节点输出题意及答案，支持内容翻页/刷新。提交受理及唯一索引机制延续P2，W008用真实insert屏障验证十账号、相同/不同/改内容键、写后失联恢复与关闭/截止竞争。最后受理前检查状态时间，已受理请求允许在关闭后落库；未加跨集合事务。

## W-009修正补记（2026-10-16）

同一次填写的匿名勾选返回修改后保留，成功后的“再填一份”才恢复默认实名。密码页面按Unicode码点校验，和服务端8—128限制一致。revision输入最大2147483647，超过返回422，恰好达到上界的管理更新409；offset最大9223372036854775807。均值精确求和与一次显示舍入修复见11；字段、路由、所有者规则及v1数据不变。此前W008记录中的仅非有限回退是历史实现，当前以本节为准。
