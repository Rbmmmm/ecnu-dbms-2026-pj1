# 技术方案比较与推荐

日期：2026-10-15。B-001—B-016业务规则已确认；本文件保留AI完成的比较理由；用户已同意推荐组合，技术方案正式采用。选型比较当时没有安装框架或做性能实测；P2以后已安装并锁定实际依赖，仍未做性能测量，不以流行度、生成代码速度或未经测量的吞吐量选型。

## 推荐组合

Python + FastAPI + PyMongo；Jinja2生成页面，HTML/CSS与原生JavaScript负责交互；页面和JSON API由同一个后端同源提供。测试采用pytest、FastAPI TestClient、真实MongoDB隔离测试集合，以及少量浏览器端到端测试。

使用已有课程Python环境前先检查，再确定兼容版本和锁定依赖。框架增加的请求模型和测试工具服务于本题接口、文档与验证要求；数据库仍使用课程熟悉的PyMongo，不引入ODM来隐藏集合、查询及索引设计。

## Python后端比较

| 方案 | 适合本题的地方 | 本题要承担的代价 | 判断 |
|---|---|---|---|
| Flask + PyMongo | 框架轻量，Jinja页面自然；数据库操作可直接沿用PyMongo；有测试客户端 | 请求结构校验、接口规范与文档需要自行组织或选扩展，保持一致需要额外纪律 | 合适的备选，若优先减少类型模型学习成本可选 |
| FastAPI + PyMongo | 以类型定义接口结构，可生成OpenAPI/交互文档；TestClient可配pytest；可独立测试业务规则 | 需要掌握请求/响应模型与数据转换边界；认证、业务校验和并发正确性仍需设计 | 推荐，接口契约、文档及第二阶段变更审查更贴合当前重点 |
| Django + MongoDB | MongoDB已有官方Django后端；可以利用较完整的应用框架 | 按本项目需要使用的功能衡量，适配后端、模型组织和框架约定的成本较高；管理后台等优势当前不需要 | 当前不优先，不能说不支持MongoDB或无法满足要求 |

官方依据：[Flask概述](https://flask.palletsprojects.com/en/stable/)、[Flask测试](https://flask.palletsprojects.com/en/stable/testing/)、[FastAPI特性](https://fastapi.tiangolo.com/features/)、[FastAPI测试](https://fastapi.tiangolo.com/tutorial/testing/)、[MongoDB官方Django后端](https://www.mongodb.com/docs/languages/python/django-mongodb/current/)。表中的适配程度为本项目判断，非官方排名。

## 前端组织方式比较

| 方案 | 当前收益 | 代价及第二阶段影响 | 判断 |
|---|---|---|---|
| Jinja2页面 + 按页组织的原生JavaScript | 一个应用提供页面和API，减少构建与部署配置；能实现题目编辑、回退、条件跳转和统计 | 交互复杂后需保持页面状态与事件组织清楚；不能把代码堆在单个脚本中 | 推荐；保留稳定API和页面模块，按需求增量扩展 |
| React + 独立前端工程 + Python API | 组件与前端状态组织适合更复杂编辑交互 | 需额外维护前端构建、依赖、接口联调与测试；独立开发服务还需处理代理或跨域 | 当前收益不足以优先采用；不声称React必然需要两个生产服务 |
| 纯表单页面、完全不使用JavaScript | 最少前端状态 | 配置多题、多规则及即时跳转会增加整页交互负担，影响演示和填写体验 | 不采用这一极端简化 |

FastAPI官方提供[Jinja模板集成](https://fastapi.tiangolo.com/advanced/templates/)。React官方的[从零构建指南](https://react.dev/learn/build-a-react-app-from-scratch)说明构建工具和路由等选择。是否值得引入组件框架取决于交互复杂度，本题已明确不要求复杂界面。

## 第一阶段如何组织以便继承

- 页面和API可以在同一服务中，但页面展示、HTTP输入输出、业务规则、数据库读写分别组织。
- Jinja模板负责页面结构，JavaScript负责局部交互；主要增改查通过明确的JSON接口完成。业务逻辑不复制进模板。
- 请求模型验证输入形状和静态约束；问卷配置决定的动态限制、权限、路径及统计仍用明确的Python业务函数处理。Pydantic模型不是MongoDB文档设计的替代品。
- 跳转、回退和提交校验共用后端规则函数。可以提供无持久化的路径校验接口供页面交互使用；服务端提交时再次校验最终路径，不能相信浏览器声明。具体接口已在12设计为evaluate，提交仍重新校验。
- 保留题目/选项稳定标识、发布冻结和历史答卷解释。新增规则、字段或统计时在相关模块增量修改，保留旧样本回归。
- 原生JavaScript按登录、问卷编辑、填写、统计等页面组织，避免第二阶段只能整页重写。当前不预设第二阶段切换前端框架；重大替换须先判断是否违背继承要求。

同步PyMongo可配同步路由处理函数，先沿用课内同步写法；不要在异步路由中直接阻塞事件循环。FastAPI关于[同步与异步](https://fastapi.tiangolo.com/async/)的说明支持按调用库选择写法。并发正确性取决于数据库操作与约束，不会因选择FastAPI或async自动成立。

AI说明15分：记录真实候选比较、选用理由、生成结果与验证；不为展示AI能力增加无关工具。
