## D-101 从访问方式确定集合

教材第3.1节要求先确定存什么、怎么存、如何访问；第3.2节比较嵌套和引用。本题主要对象是用户、问卷、答卷；会话是登录所需的辅助对象。

| 集合（逻辑名） | 内容与联系 | 主要访问 |
|---|---|---|
| users | 用户名、密码哈希、注册时间 | 按用户名登录，按ID获取当前账号 |
| surveys | 创建者引用、问卷设置、按顺序嵌入的题目、选项、校验与规则 | 我的问卷列表；一次读取完整问卷；整体保存草稿 |
| responses | 引用问卷和填写者，一份完整提交嵌入一组答案 | 按问卷统计、按题查看内容、提交防重 |
| sessions | 用户引用、随机令牌的哈希、到期时间 | 登录校验、退出、过期清理 |

题目随问卷一起读取、编辑与发布，放在问卷内部能用一次文档写入保存一致配置。答案随每次提交一起产生，嵌入答卷可避免保存半份答卷。答卷数量不断增长，不能嵌进问卷数组；否则每次填写都改同一大文档，问卷也会无限变大。用户独立存在，问卷和答卷引用用户，不复制密码或完整用户信息。

关系数据库同样能实现此系统，但本题不使用它。若按关系表逐层拆题目、选项、规则和答案，读取一份配置需要组装多个对象；本项目按问卷和答卷的读写边界组织文档，并保留跨对象引用。这不是“MongoDB不用关联”，也不意味着嵌套越多越好。没有性能实测，不声称优于其他模型。

所有持久业务数据都在MongoDB。环境变量、源代码和测试证据是运行配置与开发材料；浏览器只保留当前未提交输入，不新增SQLite、Redis或本地业务JSON存储。

## D-102 文档契约

以下是字段契约；`ObjectId`、`Date`、`Decimal128`表示BSON类型，API另做转换，不直接返回数据库文档。除明确可空字段外必填。每份顶层文档都有`schema_version: 1`。

### users

`_id: ObjectId`、`username: string`、`password_hash: string`、`created_at: Date`。

用户名去首尾空白，3—32个字符，允许中文、英文字母、数字、下划线，英文字母统一小写后存储并检查唯一；页面明确规则。密码8—128个Unicode码点，不自动trim，不存明文、不写入日志。使用`pwdlib[argon2]`的推荐密码哈希配置；登录错误统一为账号或密码错误。账号不支持改名或删除，故实名展示可按用户引用查询当前用户名。

### surveys

- `_id: ObjectId`；`owner_id: ObjectId`；`title: string`；`description: string`。
- `allow_anonymous: bool = false`；`allow_repeat: bool = false`。
- `state: draft | published | closed`；`deadline_at: Date | null`。
- `revision: int >= 1`，任何成功管理更新加1，用于拒绝覆盖旧编辑。
- `content_version: null | 1`，首次发布设1，发布后冻结内容；它和revision、schema_version不是同一种版本。
- `created_at / updated_at: Date`；`published_at / closed_at: Date | null`。
- `questions: array`，数组顺序即题目顺序，不重复存position字段。

题目共同字段：`id: UUID字符串`、`kind: single | multiple | text | number`、`title`、`required: bool`、`validation: object`、`options: array`、`rules: array`。

- 单选：options为`[{id: UUID字符串, text: string}]`，validation为空对象。
- 多选：相同options；validation含`min_choices / max_choices: int | null`。
- 文本：options为空，validation含`min_length / max_length: int | null`；rules为空。
- 数字：options为空，validation含`min_value / max_value: Decimal128 | null`、`integer_only: bool`。
- 每条rule为`{op, operand, target}`。单选op为`eq`、operand为选项ID；多选op为`any/all/exact`、operand为非空且不重复的选项ID数组；数字op为`eq/ne/gt/gte/lt/lte`、operand为Decimal128。target为后续题ID或保留字`END`。

题目和选项UUID由编辑页生成，后端校验格式与作用域唯一；它们不是权限凭证。题目ID在整卷唯一，选项ID在所属题唯一。编辑文字和排序保留ID，新增才生成ID。切换题型要清除不适用配置，发布验证禁止残留错误类型字段。规则按数组顺序评估，不另造通用脚本语言。

### responses

- `_id: ObjectId`、`survey_id / respondent_id: ObjectId`、`content_version: 1`。
- `anonymous: bool`、`repeat_allowed: bool`（从冻结问卷复制，不能接收客户端赋值）。
- `submission_key: UUID字符串`，由填写页每次有意新填写生成。
- `request_digest: string`，对规范化的内容版本、匿名选择、答案计算SHA-256，用于重试内容比较。
- `accepted_at / created_at: Date`，分别记录最后接收资格检查时刻、插入准备时刻。
- `path: [题目ID]`，包含实际经过的空答题，用于解释路径。
- `answers: [{question_id, value}]`，仅保存路径上非空答案；single值为选项ID、multiple为选项ID数组、text为去首尾空白的文本、number为Decimal128。

空答与未访问都不进入answers，path区分两者。答案不重复存题干、选项文本和用户名，因为发布内容冻结且问卷不删除；response.content_version显式说明使用哪份题意。存path是少量可解释性冗余，必须由后端推导，不能照收客户端路径。

### sessions

`_id: ObjectId`、`user_id: ObjectId`、`token_hash: string`、`created_at / expires_at: Date`。令牌用密码学随机源生成至少32字节，只把原令牌放HttpOnly cookie，MongoDB保存SHA-256；绝不复用密码哈希作为令牌。会话固定24小时，退出删除当前会话。TTL用于清理，应用每次验证仍检查expires_at。

## D-103 索引与查询

| 集合 | 索引 | 目的 |
|---|---|---|
| users | username唯一 | 并发注册不能产生同名账号 |
| surveys | owner_id升序、created_at降序、_id降序 | 我的列表及稳定分页 |
| responses | survey_id、respondent_id、submission_key联合唯一 | 重试同一提交只保存一次 |
| responses | survey_id、respondent_id联合唯一，partialFilterExpression={repeat_allowed:false} | 禁止重复的问卷，每账号最多一份，防止并发绕过 |
| responses | survey_id升序、created_at降序、_id降序 | 整卷统计范围与最新内容分页 |
| sessions | token_hash唯一 | 会话查找 |
| sessions | expires_at单字段TTL，expireAfterSeconds=0 | 清除过期会话 |

内建_id索引不重复创建。重复限制由唯一索引兜底，不用“先count再insert”冒充并发保护。每份response必须包含布尔repeat_allowed，避免缺字段绕过部分索引。建立数据库validator检查关键BSON类型、必填字段和枚举；复杂路径、跨文档关联、题目约束仍由后端负责。初始化检查索引存在且规格正确，建索引失败不得把服务标成就绪。

题目统计先按survey_id筛选答卷，再展开answers、按题及选项分组；不预存统计计数器。第一阶段先保留易读聚合，性能验收记录实际样本量和查询计划，不预先增加每题索引。新统计指标不用回写所有答卷。

官方依据：[单文档原子写与条件更新](https://www.mongodb.com/docs/manual/core/write-operations-atomicity/)、[部分索引及唯一约束](https://www.mongodb.com/docs/manual/core/index-partial/)、[TTL索引](https://www.mongodb.com/docs/manual/core/index-ttl/)。TTL删除有延迟，所以不能用“文档还在”判断会话有效。实施时再核对实际MongoDB版本和索引结果。

## D-104 数字与时间边界

API把数字题的数值、上下限和数字条件操作数传成十进制字符串，例如`"18.0"`。服务端严格解析为Decimal，拒绝bool、空白当0、NaN、Infinity和不可表示值；无损转换BSON Decimal128，不能悄悄舍入输入。API说明明确其有限精度和范围；超出表示能力返回422，不报服务器错误。页面保留用户输入字符串，不先转JavaScript Number，避免较长整数被浏览器舍入。

整数按数值判断，因此18.0通过；比较和均值不走二进制浮点。平均值用实际数字答案计算：从MongoDB流式读取Decimal128并精确求和，API average按Decimal128精度除法输出；两位显示直接从精确总和/计数按ROUND_HALF_UP求得，避免再次舍入已近似均值；空集合返回null。测试常规值、0、负数、端点、超范围和1.005显示1.01。代价是一个明确的数字序列化边界；不引入完整金额框架。[PyMongo Decimal128文档](https://pymongo.readthedocs.io/en/stable/api/bson/decimal128.html)说明转换与异常行为。

时间持久化为UTC BSON Date（毫秒精度），接口ISO 8601必须带时区，页面按Asia/Shanghai显示和输入转换；比较采用同一毫秒精度。截止等于受理时刻即拒绝，UTC不受浏览器时区影响。测试用可注入时钟，不依赖等待真实时间流逝。

## D-105 状态与更新一致性

草稿→发布→人工关闭；关闭不可重开。到期是published的计算状态，不写expired，延长截止即可重新接收。草稿保存只检查结构、类型、ID及资源限制，允许不完整题干或悬空跳转供继续编辑；发布检查完整业务有效性。编辑、发布、截止修改和关闭都按`_id + owner_id + state + revision`条件更新，revision不匹配返回409，防止两个标签页覆盖或发布后继续编辑。

发布前检查的配置必须就是条件更新锁定的revision。关闭和改截止也有revision；请求不匹配时重新读取，不静默覆盖。发布、关闭操作允许重复调用返回当前已完成状态，但不能夹带内容更新；不把过时的发布请求当作允许覆盖配置。

提交最后检查一次问卷当前状态和截止，以这次读取时的服务器时刻作为受理时刻。通过后的一次insert保存整份答卷。并发关闭允许已受理请求完成，关闭之后才通过接收检查的新请求拒绝；截止之后的重试若已有成功记录，返回原收据，不新增数据。这明确了B-008的“受理时”边界，不承诺关闭返回后绝无在途答卷落库。

受理检查与答卷插入跨集合，不称为事务原子操作。此方案避免为本地单机环境强制部署副本集；若第二阶段要求关闭与所有在途写入严格串行，需要另作事务或接收队列设计并补兼容测试。测试必须控制读到允许状态后暂停、关闭再恢复，证明这项边界。

## D-106 应用组织与权限

采用FastAPI + 同步PyMongo，涉及数据库的路由使用普通def。Jinja2页面与JSON接口同源。当前P3实际文件组织：

```text
app/
  main.py                 路由、认证归属、状态/提交、页面装配与异常转换
  config.py / db.py        配置与工程上限、连接生命周期、validator/索引检查
  schemas.py              请求结构、字段/ID/类型校验
  domain.py               发布检查、答案规范化/校验、规则匹配与路径重放
  decimal_values.py       十进制字符串及无损Decimal128转换
  time_values.py          带时区ISO与UTC毫秒边界
  statistics.py           全类型统计及内容白名单分页
  templates/page.html    同源页面骨架
  static/app.js           按页面职责组织交互函数
  static/style.css        页面样式
scripts/                   schema初始化、启动、隔离测试服务、统一验收入口
tests/                     真实MongoDB/API测试、浏览器流程、固定样本及映射
```

实际按体量合并了路由与用例，没有建立空routes/services/repositories抽象。已复用contemporary_db并固定requirements.lock.txt；历史环境与测试版本见对应证据。密码哈希方案参考[FastAPI安全教程](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)的pwdlib/Argon2部分；本项目使用会话cookie，不照搬JWT认证架构。

所有管理查询同时过滤owner_id；他人资源统一404，未登录401。填写接口只提供公开题目配置，不能返回owner内部资料、他人答案或会话数据。统计与内容输出直接构造字段白名单，匿名条目不带respondent_id、用户名、submission_key或request_digest。实名内容可附用户名。任何异常堆栈、Mongo URI、密码、cookie不回给浏览器。

cookie为HttpOnly、SameSite=Lax、Path=/，本机HTTP仅开发配置允许Secure=false；HTTPS配置为true。不启用跨域访问。所有写接口要求application/json及自定义`X-Survey-Request: 1`头，并严格核对Origin等于配置的本站源（浏览器写请求缺Origin也拒绝）；避免跨站表单和登录CSRF。集成测试发送相同头。GET不改变业务数据，输出模板转义，JavaScript用textContent呈现用户文本，禁止直接拼innerHTML。登录后跳回链接只接受本站相对路径，防开放重定向。

## D-107 资源边界与隔离

工程上限统一放配置并在页面说明：请求体1MiB；问卷最多100题、每选择题100选项、每题50规则；题干1000字符、选项200、标题200、说明5000、文本答案默认上限10000。自设长度约束不得超过工程上限。保存前核对BSON文档体积不超过8MiB预留空间，超限返回明确错误；这些是本项目运行边界，不是助教规定。

应用先本机运行，Mongo仍优先按课程规则只读诊断阿里云，失败有证据后用现有本地服务。只使用用户已提供的本人数据库；未知学号不猜测。应用集合统一前缀`survey_`，不触碰既有users等实验集合。测试使用本地独立`survey_test_<run_id>`数据库，清理前必须校验localhost、测试数据库前缀及本轮ID，禁止对云端或业务库执行drop。测试连接与业务连接分别配置，不能隐式继承同一个URI。云端缺索引或validator权限时明确记录，不静默删约束当成功。

## W-008实施补记（2026-10-15）

四集合、validator实际规格、唯一/部分唯一/TTL索引与schema/content版本保持v1；工程常量统一app/config.py LIMITS，页面由模板获得同一组值。问卷工程字段与文本答案不以UTF16 maxlength截断合法Unicode码点，服务端保留上限校验。新增响应BSON体积保护。截止输入与服务器时钟都先转UTC并截断至毫秒，等于截止拒绝；带时区日期转UTC越界返回422。

真实MongoDB8.0.32探针发现两个最大有限Decimal128的 `$avg` 返回Infinity，虽然实际均值有限。常规值继续数据库Decimal128聚合；仅聚合非有限时，statistics.finite_average按同题持久数值流式精确累加，再在Decimal128 context中除以实际计数。求和精度覆盖[-6176,6144]指数跨度并随计数增加；显示ROUND_HALF_UP两位，不走float。代价是极端值触发第二次查询；并发查询仍不承诺同一快照。没有缩窄已确认输入范围，也不把Infinity当合法业务结果。

## W-009独立检查后的修正（2026-10-16）

真实Mongo8.0.32新增有限消去反例1E34+1-1E34，P3仅非有限回退不足；改为每数字题从实际BSON流式精确累加。正负半分附近的双舍入反例进一步要求显示值直接由精确总和/计数计算：整数分子/分母的余数判断实现HALF_UP，API average仍为Decimal128精度。新增查询有成本，未声称性能提升或跨查询快照；不缩窄数值输入范围。

revision上界为既有int32最大值2147483647，达到上界的管理写入409以避免加1破坏validator；offset上界为有符号int64最大值9223372036854775807，超范围422。四集合/索引/版本/既有业务工程上限未改变，没有数据迁移。匿名选择在同一次页面填写内保留，密码按码点校验；新填写默认实名。
