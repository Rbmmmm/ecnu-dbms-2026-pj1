# 测试与证据管理

## 验收依据先于实现

AI 可以编写和运行大量测试，但测试是否检查了正确的需求仍需审查。为避免代码与测试共享同一个错误解释，每个核心功能先确定业务实例和预期结果，再实现代码。预期值不能直接调用被测统计或跳转函数生成。

需求使用 R-xxx，设计决策使用 D-xxx，测试使用 T-xxx，工作包使用 W-xxx。这些编号已在06要求索引、13样本及tests阶段映射中关联；不必给每个变量和小修复编号。

测试用例至少记录：关联需求、数据前提、步骤、输入、预期输出、实际输出、通过或失败、运行版本与时间。没有运行的用例标注“未执行”。

## 分层测试

| 层次 | 要检验什么 | 主要方法 |
|---|---|---|
| 规则测试 | 多选数量、文本长度、数字范围、整数、条件匹配与跳转路径 | 小型确定样本；最小值前后、最大值前后、空值、零值等边界 |
| API 与数据库集成 | 权限、发布和关闭、非法请求、提交保存、统计 | 使用真实 MongoDB 测试数据库，核对响应及实际文档 |
| 网页端到端 | 创建者与填写者能完成完整流程，前端提示与服务端一致 | 少量代表性自动或手工浏览器测试 |
| 并发与重复请求 | 两人同时填写不覆盖；限制重复时并发请求不能绕过；合法多次填写不被误挡 | 同步发出请求，检查成功数量、答卷条数和统计 |
| 继承回归 | 第一阶段功能和样本在变更后仍可用 | 固定数据与业务断言，必要时对迁移前后分别检查 |

并发正确性测试不等于压力测试。没有实际测量就不报告吞吐量、容量或“高并发性能”。无需为本题增加没有依据的性能指标。

## 必须覆盖的行为

- 创建和题目配置：正常输入、缺失字段、不存在的选项或跳转目标、非法约束；覆盖助教要求的创建问卷与添加题目测试。
- 校验：多选恰好数量与上下界，文字长度边界，数字范围与整数限制，非法类型。前端拒绝不够，直接调用接口也要拒绝。
- 跳转：单选、多选、数字三类；默认下一题、多规则命中、结束路径；非法循环按已确认规则处理。
- 路径一致性：未访问的题如何处理，漏答必答题如何拒绝，改变前置答案后旧分支答案是否仍应保留或统计。
- 提交：未发布、已关闭、已过期、权限限制、合法重复填写与重复请求；失败后不能留下半份有效答卷。
- 隐私与权限：用户甲不能管理用户乙的问卷或取得其私有统计；匿名数据的接口与页面符合约定。
- 统计：用少量可手算答卷检查每一项计数和平均值；包含空答卷集合、无人回答题、零值、跳过题、重复填写。
- 持久化与并发：重启后仍可读；多人提交不互相覆盖；数据库约束与应用规则一致。

上述扩展测试点服务于题意正确性，具体规则取决于 P0 决定；不得把建议的行为擅自写成老师的明确要求。

## 统计验收样本

在实现前写一份小样本，例如若干答卷中包含数字 0、10、20，以及一个因跳转而未回答数字题的答卷。若确认统计仅计算实际数字回答，期望平均值为 10，分母为 3，而不是所有答卷数。具体样本已在[13](13-验收样本与需求覆盖.md)固定，并在tests/fixtures_f01.py、fixtures-f01.json及fixtures_f02.py落地；P3实测结果见[P3证据](证据/P3-验收.md)，固定预期与实际结果分开记录。

对选择题明确重复填写时的计数单位。记录每份样本的预期路径，避免只核对最终平均值却漏掉错误分支。

## 证据保存与缺陷处理

- 测试在独立数据库运行，不清空个人其他实验的数据。测试清理操作必须限制在明确的测试数据库或集合。
- 每次正式验收保存运行时间、代码版本、环境、用例结果及必要数据库核对信息；命令或步骤必须能复现。
- 对缺陷保留输入、预期、实际、原因、修复位置及回归结果；小问题归入原工作包，不逐次生成长篇文档。
- 截图主要证明网页流程，不能替代接口、数据库和统计核对。
- 提交材料引用精简证据；内部保留足以追溯的脱敏原始结果。不得编造输出、隐藏尚未修复的失败或将计划当结论。
