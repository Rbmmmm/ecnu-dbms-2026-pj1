# 开发文档

本目录供开发推进、设计讨论和验收使用，不直接作为作业报告提交。助教要求以仓库根目录的原始 Word 及其 Markdown 转换件为准。本目录中的建议不等于已确认的需求或已实现功能。

## 接手入口

新会话先读 [交接状态](agent-handoff.md)，按 [交接工作流](09-交接工作流.md) 核对实际文件、Git 与测试。长期规则仍由根目录 AGENTS.md 和本目录专题文档维护。

5. [实践调研与采用方案](05-实践调研与采用方案.md)：官方指南、近期社区讨论、写作技能与采用依据。
6. [要求对照与每轮检查](06-要求对照与每轮检查.md)：评分映射、30 项要求索引、每轮核对和验收记录。

## 目录职责

- 根目录原始说明：保留助教材料，不混入我们的解释。
- `开发文档/`：推进计划、待决问题、设计决策记录、工作包记录、阶段验收记录。这里可以保留讨论、失败尝试和未完成事项。
- `提交文档/`：按已完成内容生成系统设计、使用与 API 说明、测试报告、AI 使用日志、项目完成报告。已创建七份按实际实现编写的说明及报告审核稿，PDF格式来自2026-10-16用户新要求；具体状态见交接。
- `tests/`：已存放P2/W007/P3/P4/P6可重复运行的测试、固定样本、阶段映射及AI审查记录。
- `开发文档/证据/`：已存放P1设计及P2/W007/P3/P4脱敏验收结果、P6技术通过但待终审/发布的结果、必要截图及变更证据；按所属版本保留，不把旧证据当作当前状态。不得放密码、连接凭据、真实敏感答卷。

提交时按明确清单打包，不将开发目录整体作为报告附件。可从开发证据中选取必要内容放入提交文档附件。

## 持续维护约定

每个工作包结束时，由 AI 更新工作记录、相关设计决策、测试结果和推进状态；用户不需要手工抄录聊天。已确认规则保持有效；用户已授权后续设计按原则直接推进。常规实现、小修复和记录整理可连续完成，新的实质业务冲突再澄清。

状态只使用：未开始、进行中、待决策、验收失败、已验收。计划中的内容不得写成已经实现，未执行测试不得写成通过。

当前进度、实物检查结果及下一步统一见 [交接状态](agent-handoff.md)。本文件不重复维护进度快照，避免多处状态不一致。

教材依据：从课程根目录查阅 `教材/onlineDBMSbook/chapter3.1.md` 与 `chapter3.2.md`。前者提供需求、概念、逻辑、物理设计及实施维护的流程，后者用于比较嵌套与独立集合的访问代价。设计方案必须结合本题访问方式判断，不能直接照搬博客示例。

P4独立检查的范围、步骤与预期见[W-009](W-009-独立检查.md)；实际运行状态仍只以交接和阶段证据为准。
